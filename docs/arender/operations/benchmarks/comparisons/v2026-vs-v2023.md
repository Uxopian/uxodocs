# ARender 2026 vs 2023 — Performance comparison

This report is a **non-regression check**: it confirms that ARender 2026.0.0 performs at least as well as the previous public release on the same infrastructure, with the same scenario, at the same load. Captured in **April 2026** between **ARender v2026.0.0** (the first major-line release) and **ARender v2023.19.0** (the last public minor of the v2023 line at the time).

| Versions compared | **ARender 2026.0.0** vs **ARender 2023.19.0** |
|---|---|
| Test date | April 2026 |
| Test scope | **ARender Rendition backend only** (broker, converter, renderer, text handler) |
| Tooling | Gatling, one-hour run on each version |
| Workload | **~32,000 documents/hour** (278 req/s) on each version |
| Infrastructure | Production-class Linux Kubernetes cluster, three worker nodes (32 GB RAM each), identical configuration across both runs |

:::caution Scope reminder
The comparison covers **the Rendition backend only**. End-to-end performance in your own deployment also depends on the UI tier, your document source connector, network, and authentication path. The deltas below reflect software-level improvements between the two ARender versions on an identical infrastructure profile.
:::

This page summarises the headline delta. See the [Performance benchmarks index](../index.md) for the shared scenario and methodology, or the per-version pages — [ARender 2026.0.0](../v2026/v2026.0.0.md) and [ARender 2023.19.0](../v2023/v2023.19.0.md) — for the standalone figures.

## Headline results

| Indicator | v2023.19.0 | v2026.0.0 | Change |
|---|---|---|---|
| Document layout — **P99** | 1,656 ms | **377 ms** | **−77%** |
| Document layout — **Mean** | 294 ms | **197 ms** | **−33%** |
| Global response time — **P99** | 269 ms | **240 ms** | **−11%** |
| Global response time — **Max** | 21,785 ms | **14,631 ms** | **−33%** |
| Error rate | 0% | **0%** | Unchanged |
| Total requests over the one-hour run | 1,003,914 | 1,001,652 | Equivalent |

The dominant gain is on document layout, the endpoint that determines how quickly a document opens for the end user. Tail latency dropped by 77% at the 99th percentile and the standard deviation dropped from 684 to 180, indicating much more consistent open times across the document corpus.

## Per-endpoint results

The table below lists the endpoints that **improved** or remained **statistically equivalent** between the two versions. Endpoints not shown remained within the same operational envelope as the baseline.

| Endpoint | P50 (v2023.19.0) | P50 (v2026.0.0) | P99 (v2023.19.0) | P99 (v2026.0.0) | Verdict |
|---|---|---|---|---|---|
| Open document by URL | 18 ms | 18 ms | 42 ms | 40 ms | Stable |
| Get document layout | 228 ms | **185 ms** | 1,656 ms | **377 ms** | **Improved** |
| Evict document | 10 ms | 11 ms | 38 ms | 53 ms | Stable |

All values in milliseconds. P50 is the median; P99 captures the slowest 1% of requests (tail latency).

## Stability

Both runs completed with **0% error rate** over approximately one million HTTP requests each. ARender v2026.0.0 sustained the target throughput for the full hour without any failed request, matching the reliability profile of the v2023.19.0 baseline.

The reduction in maximum observed response time (21,785 ms → 14,631 ms, −33%) confirms that the improvements extend to the worst-case behaviour, not only to the typical or near-typical request.
