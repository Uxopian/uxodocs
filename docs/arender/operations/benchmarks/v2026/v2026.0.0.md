# ARender 2026.0.0 — Performance

| Version under test | **ARender 2026.0.0** |
|---|---|
| Test date | April 2026 |
| Test scope | **ARender Rendition backend only** (broker, converter, renderer, text handler) |
| Reference infrastructure | Three-node Linux Kubernetes cluster, 8 vCPU / 32 GB RAM per worker node |
| Tooling | Gatling, one-hour LOAD run |

This page reports validated performance figures for the ARender Rendition backend at v2026.0.0, captured on a reference infrastructure profile. The numbers serve two purposes:

1. **Non-regression check** against the previous public release. See the [ARender 2026 vs 2023 comparison](../comparisons/v2026-vs-v2023.md) for the version delta on identical infrastructure.
2. **Sizing reference for the Rendition tier**, so customers can map their expected document workload to the infrastructure footprint required to serve it.

:::caution Scope reminder
These figures measure **the Rendition backend in isolation** — broker, converter, renderer, text handler. End-to-end performance in your own deployment also depends on the UI tier, your document source connector (DMS, ECM, S3, …), network, and authentication path. Use these numbers as a *Rendition-tier sizing reference*, not as a guaranteed end-to-end throughput.
:::

## Reference benchmark

On the reference infrastructure (three-node Kubernetes cluster, 8 vCPU / 32 GB RAM per worker), the Rendition backend sustains the following throughput over a continuous one-hour run:

| Indicator | Value |
|---|---|
| **Documents served per hour** | **~32,000** (8.87 docs/s) |
| HTTP throughput | 278 req/s |
| Total HTTP requests over the one-hour run | 1,001,652 |
| Error rate | **0%** |
| Global P50 | 19 ms |
| Global P95 | 150 ms |
| Global P99 | 240 ms |
| Mean response time | 35 ms |

:::tip Sizing your Rendition tier
The reference figure (~32,000 docs/hour) translates directly to the Rendition-tier capacity you need. For example, assuming **20 documents opened per user during the busy hour** (≈ one document every three minutes — representative of moderate ECM and case-management workloads):

- This reference infrastructure handles **~1,600 active users** (32,000 ÷ 20) on the Rendition tier during the busy hour.

Substitute your own per-user document rate to size accordingly: `users on Rendition tier ≈ docs-per-hour ÷ docs-per-user-per-hour`. The other tiers of your deployment (UI, connector, DMS) need to be sized separately based on the same user count.
:::

## Per-endpoint latency

| Endpoint | Total requests | P50 (ms) | P95 (ms) | P99 (ms) | Mean (ms) |
|---|---|---|---|---|---|
| Open_document_with_url | 31,966 | 18 | 29 | 40 | 20 |
| Get_document_layout | 31,966 | 185 | 279 | 377 | 197 |
| Get_3_images | 53,278 | 90 | 260 | 308 | 128 |
| Get_20_thumbnails | 223,774 | 30 | 69 | 124 | 34 |
| Get_3_pages_content | 628,702 | 16 | 46 | 98 | 21 |
| Evict_document | 31,966 | 11 | 25 | 53 | 13 |

`Get_3_pages_content` is by far the highest-volume endpoint (over 628k requests in the one-hour run) and is among the fastest of the rendition operations.

## Stability

ARender v2026.0.0 served **1,001,652 HTTP requests** over the one-hour run with a **0% error rate**. Pod-level resources (CPU, memory, network) remained stable for the duration of the run.

## Scaling validation

The Rendition backend was also exercised at doubled concurrency on the same infrastructure as a proportionality check. Document throughput scaled near-linearly to ~57,000 documents/hour (+77%) while global P95 and P99 remained effectively flat, confirming that the architecture has additional headroom for higher document rates on the same infrastructure profile when needed.

## Methodology footnote

The reference benchmark uses a closed-injection Gatling run at 10 concurrent virtual users sustaining ~278 HTTP req/s for one hour, executing the standard per-document scenario described in the [benchmarks index](../index.md#methodology). The scaling-validation run uses the same scenario at 20 concurrent virtual users.

## Comparing against earlier versions

For a direct comparison of these numbers against the v2023.19.0 baseline on the same infrastructure, see the [ARender 2026 vs 2023 comparison](../comparisons/v2026-vs-v2023.md). Headline: a 77% reduction in document-layout P99 and an 11% reduction in global P99 with no regressions.
